# ドメインチェッカー改良 設計仕様書

## 概要

画面項目定義とテーブル定義の2ファイルをアップロードし、
既存のドメイン一覧とのマッチングを行い、一致率・候補を提案するツール。

---

## 1. インプット

### 1-1. 画面項目定義

- **シート名**: 画面項目定義（config で変更可能）
- **ヘッダー検索方式**: 部分一致（含む）。自動ヘッダー行検出あり。
- **対象列**:

| 列名 | 用途 |
|------|------|
| 項目名称 | マッチングキー |
| 型 | 大分類判定 |
| テキストタイプ | ドメインデータ型の絞り込み |
| 最小桁 | 桁数照合 |
| 最大桁 | 桁数照合 |
| 最大バイト数 | バイト長照合 |
| 最小値 | 数値範囲照合 |
| 最大値 | 数値範囲照合 |
| 外部コード | 外部コード照合 |

- **対象外判定**: 項目名称のみあり、テキストタイプ〜外部コードの7列が全て空 → 「対象外」

### 1-2. テーブル定義

- **シート名**: テーブル定義（config で変更可能）
- **ヘッダー検索方式**: 部分一致（含む）。自動ヘッダー行検出あり。
- **対象列**:

| 列名 | 用途 |
|------|------|
| 論理項目名 | マッチングキー |
| データ型 | 大分類判定 |
| Length | 桁数照合 |
| 全体数値 | 整数部照合 |
| 少数桁 | 小数部照合 |

- **対象外判定**: 論理項目名のみあり、データ型〜少数桁の4列が全て空 → 「対象外」
- **テキストタイプなし**: テーブル定義にはテキストタイプがないため、大分類＋桁数のみで判定
- **型文字列からの桁数補完**: `varchar2(20)` や `number(10,2)` のような型文字列から Length / 整数部 / 小数部を自動補完する

### 1-3. ドメイン一覧（既存・アップロード不要）

- **ヘッダー検索方式**: 部分一致（含む）
- **対象列**:

| 列名 | 用途 |
|------|------|
| ドメイン名 | マッチング結果として出力 |
| データ型 | 大分類・詳細型判定 |
| カラム定義 | 型名・桁数の補完（`char(12)` 等から抽出） |
| 最小文字数 | 文字列桁数照合 |
| 最大文字数 | 文字列桁数照合 |
| 最小バイト長 | バイト長照合 |
| 最大バイト長 | バイト長照合 |
| 最小値 | 数値範囲照合 |
| 最大値 | 数値範囲照合 |
| 整数部桁数 | 数値桁数照合 |
| 小数部桁数 | 数値桁数照合 |
| 書式（正規表現） | 参考情報 |
| 参照外部コード | 外部コード照合 |

- **カラム定義からの補完**: `char(12)` → 最大文字数=12、`number(10,2)` → 整数部桁数=8、小数部桁数=2 のように自動補完

### 1-4. ドメイン一覧のデータ型一覧

| 分類 | データ型 |
|------|---------|

| 全角系 | 全角文字、全角英字、全角数字、全角ひらがな、全角カタカナ、全角英数字、全角英数字記号 |

### 判定結果の値

| 値 | 意味 | 内部 match_type |
|----|------|-----------------|
| 完全一致 | 項目名＋型＋桁数が全て一致 | `exact` |
| 選択必須 | 人間の選択が必要（フラグ/コメント/補記） | `special_flag`, `special_comment`, `human_choice` |
| 提案（候補から） | 既存ドメインから候補を提案 | `suggested`, `no_match`, `unmatched` 等 |
| 提案（新規） | 既存に該当なし → 新規ドメイン提案 | `new_domain`, `no_type_digits_match` |
| 提案（候補）同名/桁違い | 同じ項目名のドメインが存在するが桁数が異なる | `suggested`（name_match_mismatch=True） |
| 対象外 | 属性列が全て空のためマッチング不要 | `unnecessary`, `out_of_scope` |

### 重複排除の基準

- **項目名（末尾数字除去後）＋桁数**が完全一致していたら重複とみなし1つに集約

### 抽出シートの参照方式

- INDEX/MATCH 関数で重複排除シートの検索キー列と照合し、判定結果・一致ドメイン名・提案ドメイン名・候補名・汎化候補名・備考を参照する
- 検索キー = 項目名（末尾数字除去後）＋ "_" ＋ 桁数

### ヘッダー色分け

- 入力列: 青系（`#D9EAF7`）
- 判定列: 橙系（`#FFE5CC`）
- 判定結果セル色: 完全一致=緑、提案=黄、選択必須=橙、対象外=灰

## 3. マッチングロジック

### 3-1. 全体フロー

```
項目
 │
 ├─ 対象外判定
 │   → 属性列が全て空なら「対象外」で終了
 │
 ├─ 特殊パターン判定
 │   ├─ フラグ: 項目名に「フラグ」含む + boolean/0,1
 │   │   → 「以下から選択: 0/1, 0/9, null/1, スペース/1」と記載
 │   ├─ コメント/補記: 項目名に「コメント」「補記」「備考」「メモ」含む
 │   │   → 「改行あり/なしを確認して選択してください」と記載
 │   ├─ 日付（汎用）: 型=date + yyyyMMdd → 汎用日付ドメイン
 │   ├─ 日付（個別）: 型=string + yyyy/MM等 → 個別ドメイン定義必要
 │   └─ 該当すれば確定（C方式で is_resolved=True）
 │
 ├─ 項目名一致判定（名前のみ。型/桁数は見ない）
 │   → 数字除去 + コード/ID/番号 除去後の文字列完全一致
 │   → 一致有無を「和名一致フラグ」として保持
 │
 ├─ 型フィルタ + 桁数一致判定
 │   → 和名一致 + 型/桁数一致 → 「完全一致」で確定
 │   → 和名一致だが型/桁数不一致 → LLM提案 + 注意文言
 │     「注意: 同じ項目名で別桁/別データ型があります」
 │   → 和名不一致 → LLM候補作成へ
 │
 ├─ テキストタイプで絞り込み（画面項目定義のみ）
 │
 ├─ C方式: 項目名の部分一致＋同義語辞書で材料収集
 │   → 類似度・桁一致率・同義語ヒット・部分一致スコアを計算
 │   → LLM候補の絞り込み（和名一致あり: 通常下限 / なし: 桁一致必須）
 │
 └─ B方式: LLMに材料を渡して最終判定
      → 提案（候補から） / 提案（新規） / 選択必須
```

### 3-2. 型の大分類マッピング

設定ファイル `type_mapping.yaml` で管理する。

| 大分類 | 画面項目定義の「型」 | テーブル定義の「データ型」 | ドメイン一覧の「データ型」 |
|--------|---------------------|------------------------|------------------------|
| 文字列系 | テキスト、テキストエリア、テーブルカラムテキスト等 | CHAR, VARCHAR, NCHAR, NVARCHAR, CLOB | 半角文字、半角英字、半角数字、半角カナ、半角英数字、半角英数字記号、全角文字、全角英字、全角数字、全角ひらがな、全角カタカナ、全角英数字、全角英数字記号、全半角混合 |
| 数値系 | 数値 | NUMBER, INT, INTEGER, DECIMAL, FLOAT, NUMERIC, BIGINT | 数値（整数）、数値（少数） |
| 日付系 | 日付 | DATE, TIMESTAMP | 日付 |
| 真偽値系 | チェックボックス | ― | 真偽値 |
| コード系 | コンボボックス、ラジオボタン | ― | コード |
| バイナリ系 | ― | RAW, ROWID | ― |

- 画面項目定義の型は多種多様で完全なマッピングは不可能
- **型は大分類レベルで参考にし、桁数での判断をメインとする**
- **コード系と文字列系は互換扱い**（コンボボックス/ラジオボタンの値はVARCHARで格納されるため）
- 大分類が「不明」の場合は除外しない（LLMに判断を委ねる）

### 3-3. テキストタイプ → ドメインデータ型の対応

設定ファイル `text_type_mapping.yaml` で管理する。

| 画面テキストタイプ | ドメインデータ型の候補 |
|-------------------|---------------------|
| 半角英字 | 半角英字 |
| 半角数字 | 半角数字 |
| 半角英数字 | 半角英数字 |
| 半角カナ文字 | 半角カナ |
| 半角文字 | 半角文字、半角英数字記号 |
| 全角文字 | 全角文字、全角ひらがな、全角カタカナ等 |
| 全半角混合 | 全半角混合 |
| その他/未指定 | 全候補から桁数で判定 |

- テーブル定義にはテキストタイプがないため、大分類＋桁数のみで判定（精度はやや低い → LLM補助が有効）
- テキストタイプで絞り込んだ結果が空になる場合はフォールバック（全候補）

### 3-4. 型・桁数照合の対応関係

入力ソースごとに比較戦略が異なる。

#### 比較A: テーブル定義 vs ドメイン一覧

ドメイン定義に「カラム定義」列がある場合、Oracle型同士で直接比較する（本命ルート）。
カラム定義列がない場合は、データ型の大分類比較にフォールバックする。

**カラム定義列ありの場合（Oracle型直接比較）:**

| テーブル定義 | ドメイン一覧 | 備考 |
|---|---|---|
| データ型 | カラム定義 | Oracle型同士（例: `NUMBER` vs `NUMBER`） |
| 桁数（数値全体桁数/整数） | カラム定義の桁 | 全体桁数 |
| 整数桁 | 整数桁 | 整数部桁数 |
| 少数桁 | 小数部桁数 | 小数部桁数 |
| Length（文字列の場合） | 文字列長 | 文字列長 |

**カラム定義列なしの場合（フォールバック）:**

| テーブル定義 | ドメイン一覧 | 備考 |
|---|---|---|
| データ型 | データ型 | `normalize_data_type()` で正規化後に大分類比較 |
| Length | 最大文字数 or 最大バイト長 | 文字列系 |
| 全体数値 | 整数部桁数 | 数値系 |
| 少数桁 | 小数部桁数 | 数値系 |

#### 比較B: 画面項目定義 vs ドメイン一覧

画面項目定義はOracle型を持たないため、日本語データ型同士で比較する。

| 画面項目定義 | ドメイン一覧 | 備考 |
|---|---|---|
| テキストタイプ | データ型 | 日本語データ型同士（例: `半角英数字` vs `半角英数字`） |
| 最大桁（文字列の場合） | 文字列～最大桁 | 文字列長 |
| 最大バイト数 | 最大バイト長 | バイト長 |
| 最小値 | 最小値 | 数値範囲 |
| 最大値 | 最大値 | 数値範囲 |

#### 外部コード（画面のみ）

| 画面項目定義 | ドメイン一覧 |
|---|---|
| 外部コード | 参照外部コード |

#### 桁数の正規化

- `12.0` → `12` のように小数点以下の `.0` は除去して比較する
- `CHAR(12 BYTE)` / `VARCHAR2(20 CHAR)` のような表記からも型名と桁数を抽出する

### 3-5. 項目名の比較ルール

- **末尾の数字のみ除去して比較**（「ああ1」→「ああ」、「TEL2」→「TEL」）
  - 中間の数字は除去しない（「1月売上」→「1月売上」のまま）
- 型＋桁数一致が大前提。不一致なら項目名は見ない
- 完全一致の名前比較では**コード / ID / 番号**のサフィックスを除去して比較する

### 3-6. 日本語類似度判定（C→Bパイプライン）

#### C方式（前処理・材料収集）— `domain_matcher.py`
- 接頭辞・接尾辞の部分一致
- 同義語辞書（`synonyms.yaml` で外出し）で判定
  - 例: 金額≒代金、名称≒名前、番号≒No 等
- 部分一致率、同義語ヒット有無、特殊パターン判定結果を収集
- 候補スコア = 桁一致率 0.6 + 類似度 0.4 + 同義語ヒット加点
- LLM候補の下限フィルタ:
  - **和名一致あり** → 通常の下限（config の min_sim / min_digit）
  - **和名一致なし** → 桁一致必須（min_digit_rate=1.0）

#### B方式（LLM最終判定）— `llm_matcher.py`
- C方式が集めた材料を受け取り、意味的類似度を最終判断
- バッチで投げてコスト最適化（バッチサイズ: config の `LLM_MATCHING_BATCH_SIZE`、デフォルト20）
- LLM判定結果は「候補提案」として出力（自動確定はしない）
- LLMが返す match_type: `suggested` / `human_choice` / `no_match` / `new_domain`

### 3-7. 特殊パターン

設定ファイル `special_patterns.yaml` で管理する。

| パターン | 条件 | 出力 | 内部 match_type |
|----------|------|------|-----------------|
| フラグ | 項目名に「フラグ」「flag」「FLG」含む + boolean/0,1 | 「以下から選択: 0/1, 0/9, null/1, スペース/1」 | `special_flag` |
| コメント | 項目名に「コメント」含む | 「改行あり/なしを確認して選択してください」 | `special_comment` |
| 補記 | 項目名に「補記」「備考」「メモ」含む | コメントと同様 | `special_comment` |
| 日付（汎用） | 型=date/datetime/timestamp + yyyyMMdd形式 | 汎用日付ドメイン自動割当 | `special_date` |
| 日付（個別） | 型=varchar/char/テキスト + yyyy/MM等の書式 | 個別ドメイン定義必要 | `special_date_individual` |

### 3-8. 新規ドメイン提案

既存ドメインに該当がない場合、新規ドメインを提案する。

- **提案名**: 項目名から末尾数字を除去した文字列
- **提案内容**: 入力側の属性（データ型・桁数等）からドメイン定義を自動生成
- **汎化グルーピング**: 新規提案同士で類似度が高いものをグループ化
  - ローカル類似度（SequenceMatcher）で事前グルーピング（閾値: 0.75）
  - LLM有効時はLLMで上書き判定
  - 出力シートの「汎化候補（新規内）」「同義候補（新規内）」列に反映

## 4. 設定ファイル（YAML外出し）

以下は設定ファイルで管理し、コード内定数にしない。
統一ローダー `config_loader.py` で読み込む（モジュール変数キャッシュ付き）。

### 4-1. 同義語辞書 — `synonyms.yaml`

項目名の日本語同義語グループ。`synonyms.py` がロードとAPIを提供する。

```yaml
groups:
- - 金額
  - 代金
  - 額
  - 価格
```

### 4-2. 型の大分類マッピング — `type_mapping.yaml`

画面型・テーブル型・ドメイン型の対応表。Section 3-2 の定義に準拠。

```yaml
categories:
  文字列系:
    screen_types: [テキスト, テキストエリア, ...]
    table_types: [CHAR, VARCHAR, ...]
    domain_types: [半角文字, 半角英字, ...]
```

### 4-3. テキストタイプマッピング — `text_type_mapping.yaml`

画面テキストタイプからドメインデータ型候補への変換。Section 3-3 の定義に準拠。

```yaml
mappings:
  半角英字: [半角英字]
  半角数字: [半角数字]
default_behavior: "全候補から桁数で判定"
```

### 4-4. 特殊パターン — `special_patterns.yaml`

フラグ・コメント・補記・日付の条件と出力。Section 3-7 の定義に準拠。

```yaml
patterns:
  flag:
    keywords: [フラグ, flag, FLG]
    output: "以下から選択: 0/1, 0/9, null/1, スペース/1"
  comment:
    keywords: [コメント]
    output: "改行あり/なしを確認して選択してください"
```

### 4-5. テキスト正規化（normalize_text / normalize_data_type）

同義語の正規化ルール（例: 価格→金額、flag→フラグ）は YAML 設定ファイルで管理する。
`normalize_text()` と `normalize_data_type()` はコード内定数ではなく YAML を参照する。
