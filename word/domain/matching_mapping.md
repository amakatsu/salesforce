## 6. 項目名の一致ルール

| ルール | 内容 |
|---|---|
| 数字除去 | 項目名末尾の数字を除去して比較する（例: 顧客名1 → 顧客名） |
| 前提 | **候補抽出の前提は型一致（大分類＋細分類）**。桁数は「一致率」として評価し、完全一致でなくても候補に残す |
| 類似度 | 類似度計算では **コード / ID / 番号** を除外して比較する |
| 完全一致/同義語 | **コード / ID / 番号** を除外したうえで比較する |
| 完全一致の条件 | **名前一致 + 桁数一致** が満たされた場合のみ完全一致とする |

## 9. 同義語・部分一致の扱い

### 9-1. 同義語辞書
- ファイル: `synonyms.yaml`
- 形式: グループ形式（同義語集合）
- 判定方法:
  - **両方に同義語が含まれる** 場合にヒット
  - **片側一致**でも、類似度が十分高い場合はヒット扱い（意味補強）
  - ヒット情報は **LLMへ渡す材料** になる（自動確定にはしない）

### 9-2. 部分一致
- 接頭辞/接尾辞の一致率を算出
- 類似度（fuzzy）と合わせて **LLMへ渡す材料** とする

### 9-3. LLMへの渡し方
- 大分類一致済み候補のみをLLMへ渡す（最大20件）
- **下限フィルタ**: 類似度/桁一致率が一定以下の候補は除外
- 候補ごとに以下の情報を含める:
  - 類似度
  - 桁一致率
  - 同義語ヒット有無
  - 部分一致スコア
  - 桁数照合の詳細

### 9-4. LLMの判断基準（提案）
**前提**: LLMは **日本語の意味比較と桁一致率を同じ重要度** で評価し、「類似度」は参考情報として扱う。  
**データ型（大分類）一致は前提条件**として扱う。

追加:
- **和名が異なっていても意味が近く、データ型/桁数が一致する既存ドメイン**がある場合は、
  新規提案の際に **汎化候補（既存ドメイン名）** を併記する。
- さらに新規提案同士で **型/桁が一致し名称が近いもの** は、汎化候補（新規内）としてまとめる。
**根拠が十分かどうか**は以下の基準で判断する。

1. **候補提案（suggested）にする条件**
   - 意味が一致している **かつ**
   - 桁一致率が高い（目安: 0.80以上）

2. **新規提案（new_domain）にする条件**
   - 意味が一致していても桁一致率が低い
   - 桁一致率が高くても意味が一致しない
