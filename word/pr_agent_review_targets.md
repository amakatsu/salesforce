# PR-Agent レビュー対象整理メモ

## 前提整理

| 観点 | 期待精度 | 備考 |
| --- | --- | --- |
| コード/設定の静的検査 (API/YAML/SQL/Shell 等) | 高 (自動で十分) | フォーマットや構文、共通ベストプラクティスは自動検出が期待できる |
| 設計/リーダビリティ (LWC, Java, DTO 等) | 中 (ヒューリスティック) | 観点を明示すれば指摘可能。ただし主観が残るため最終判断は人手 |
| 文章/README/仕様の網羅性 | 低 (補助) | 構造的な抜けは検出できるが内容の正確性は保証できないため今回のAIレビュー対象外 |
| ドメイン/業務ロジック, 組織固有ガイド | 不可 (対象外) | 業務知識が必要なためPR-Agentでは判断不能。必ず人手レビュー |

- **期待精度の意味**: 『高』=自動検出で信頼可、『中』=ヒューリスティックで指摘可だが人手補強推奨、『低』=補助レベル、『不可』=PR-Agent単独では対応不可。
- **ドメイン固有の要件**や規制/契約ルール等は今回のAIレビュー対象外。必ず人間の業務知識でカバーする。

## 次に決めること
- テーブルの `担当者` 列を埋め、どの観点を誰がレビューするか決める
- ガイドライン/資料が多すぎるとプロンプトが冗長になるため、カテゴリごとに最小限（例: 命名規約 + セキュリティポリシー）のガイドを明示するルールを決める
- 上記を踏まえ、この表を使った PR-Agent プロンプトテンプレートを整備し、実際のレビュー手順に組み込む
