# 命名規約

> **本ドキュメントの位置付け**: ringi 配下の各機能で共通に従う命名規約を規定する汎用設計ルール。
> **隣接ドキュメント**: 配置ディレクトリは [アーキテクチャ.md](アーキテクチャ.md)、自動生成ルールおよび JAX-RS アノテーション禁則は [設計ルール.md](設計ルール.md) を参照。

## 命名規約一覧

| 観点 | ルール |
| --- | --- |
| サービスクラス名（物理） | 機能 ID から記号を除去したキャメルケース |
| サービスクラス名（論理） | 業務上の名称 |
| ディレクトリ命名 | `{画面ID_画面名}` 形式で `presentation/api/impl` 配下と `domain/service` 配下に作成 |
| API エンドポイントクラス | `xxxxApi.java`（`xxxxResource.java` は **不可**）— RESTful 設計ではなくアクションベース RPC を採用しているため |
| Table Mapper | MyBatis Generator が自動生成。実装クラスは MyBatis-CDI が起動時に自動生成するため開発不要 |
| Query Mapper（XML） | 手動作成または自作ツールで生成（MyBatis Generator では自動生成不可） |
| サービスクラス作成単位 | **イベント毎に 1 サービスクラス**。1 サービス内に複数イベント実装は推奨しない（保守性・可読性の観点） |
| ServiceDto | Service クラスごとに Input / Output 各 1 つ（資源数 = Service × 2） |

## API エンドポイントクラス命名の根拠

JAX-RS では、一般的に API エンドポイントクラスは `XxxxResource.java` という名前付けになることが多い。これは API システムが RESTful 設計のもとリソース指向アーキテクチャを採用していることが前提のネーミングである。

本システムにおいては、RESTful な API ではなく、**アクションベースの RPC 方式** を採用しているため、`Resource` と命名するのは不適切である。

よって、本システムにおける API エンドポイントクラスは `xxxxApi.java` という命名規則を採用している。
