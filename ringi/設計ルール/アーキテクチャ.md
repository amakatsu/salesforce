# アーキテクチャ（レイヤード 3 層）

> **本ドキュメントの位置付け**: ringi 配下の各機能で共通に従うレイヤード 3 層構造（presentation / domain / infra）と、各層の責務・配置ディレクトリを規定する汎用設計ルール。
> **隣接ドキュメント**: 命名規約は [命名規約.md](命名規約.md)、設計パターン詳細は [設計ルール.md](設計ルール.md)、DB アクセス方針は [DBアクセス.md](DBアクセス.md)、プロジェクト全体の前提は [前提事項.md](前提事項.md) を参照。

## ディレクトリ構成（新方式）

新規実装はこの構成に従って配置する。

```
project
└── src/main
    ├── java
    │   └── jp/mufg/bk/yus
    │       ├── com
    │       │   ├── constant
    │       │   └── util
    │       ├── presentation                  # プレゼンテーション層
    │       │   └── api
    │       │       ├── interfaces
    │       │       └── impl
    │       │           └── {画面ID_画面名}
    │       │               ├── model
    │       │               └── mapper        # Model ↔ ServiceDto 変換 (MapStruct)
    │       ├── domain                        # ドメイン層
    │       │   ├── service
    │       │   │   └── {画面ID_画面名}
    │       │   │       ├── dto
    │       │   │       ├── util
    │       │   │       ├── const
    │       │   │       └── mapper            # ServiceDto ↔ Entity 変換 (MapStruct)
    │       │   ├── repository
    │       │   │   ├── api/interfaces
    │       │   │   └── dbaccess
    │       │   │       ├── tables/interfaces
    │       │   │       └── query/interfaces
    │       │   └── entity
    │       │       ├── api
    │       │       └── dbaccess
    │       │           ├── tables
    │       │           └── query
    │       └── infra                         # インフラストラクチャ層
    │           ├── repository
    │           │   ├── api/impl
    │           │   └── dbaccess
    │           │       ├── tables/impl
    │           │       └── query/impl
    │           └── mapper
    │               ├── tables                # 単一テーブル CRUD (MyBatis @Mapper)
    │               └── query                 # 結合 SQL 用 Java I/F (MyBatis)
    └── resources
        └── jp/mufg/bk/{システムID}
            └── infra
                └── mapper
                    └── query                 # 結合 SQL 定義 (MyBatis XML)
```

## 各層の責務

| 層 | 責務 | 禁止事項 |
| --- | --- | --- |
| presentation | HTTP リクエスト受付、入力単体・相関チェック、`ServiceDto` への詰替、レスポンスフォーマット変換 | **DB アクセス禁止**。ビジネスルール禁止 |
| domain | ビジネスロジック、トランザクション境界宣言、DB 上のデータとの整合性チェック | UI/DB の変更影響を受けてはならない。他層への依存禁止 |
| infra | DB 永続化、外部連携（API）。製品依存（Oracle / MyBatis 等）の影響を上位層へ漏らさない | 上位層への製品依存漏出禁止 |

### presentation 層の補足

- 表示における関心事を取り扱う層。クライアントからのリクエスト受付、入力データの妥当性チェック（入力項目相関チェックを含む）、リクエスト内容に対応するドメイン層の呼び出しを担う。
- Web アプリケーションで扱う HTTP リクエストやクエリパラメータといった「表示に関する技術」はこの層で吸収し、下位層には影響させない。
- この層で行う実装は **できるだけ薄く保たれるべき** であり、ビジネスルールを含んではいけない。

### domain 層の補足

- アプリケーションのコアとなる層であり、ドメインに関する具体的な業務処理（ビジネスロジック）を担う。
- 業務処理は **UI や DB に変更があったとしても不変** でなければならず、他のどの層にも依存しない設計とする必要がある。
- 設計パターンの選択方針は [設計ルール.md](設計ルール.md) を参照。
- **排他制御は domain 層の責務**。共通ライブラリ「排他制御ヘルパー」（楽観ロック）を `Service` から呼出して実現する。**DB レベルのロック（`FOR UPDATE` 等）の使用は禁止** とし、infra 層に DB 行ロックを目的としたメソッドを置かない。詳細は [DBアクセス.md](DBアクセス.md) の「排他制御（楽観ロック原則）」を参照。

### infra 層の補足

- 上位のレイヤーを支える技術的な機能を提供する。DB への永続化や外部アプリへの接続を担う。
- インフラストラクチャ層は製品に依存した実装となるため、製品変更の影響が大きい。この影響が上位層に漏れ出ないような設計が必要。
- 例えば DB が Oracle から PostgreSQL に変わる場合でも、ドメイン層やアプリケーション層には変更が一切入らないようにする必要がある。
- そのため、インフラストラクチャ層と上位層とのやり取りはインターフェースや POJO クラスを介して行う。

#### infra 層の主要実装クラス

- **RepositoryImpl**: ドメイン層の `Repository` インターフェースの実装クラス。`Repository` インターフェースによってサービスクラスから隠蔽された外部連携の具体的なロジックを実装する。ドメイン層から連携された DTO を外部連携仕様に合わせてフォーマット変換したり、外部連携先から取得したデータをドメインロジックが使いやすいように加工したりする。
- **RepositoryImpl(DB)**: DB アクセスを担うリポジトリ実装クラス。本システムでは MyBatis を利用するので、このクラスで MyBatis の機能を利用しつつ DB アクセスを実現する。
- **RepositoryImpl(API)**: API 連携を担うリポジトリ実装クラス。**`RestClient` を利用して他システムや他アプリケーションに API を送信する**。他システムからエラーが返却される場合のエラーハンドリングも行う。

## 機能別資源と配置の指針

各機能は以下の資源を、対応するレイヤに配置する。具体的な機能ごとの資源一覧は当該機能の `design/02_new_implementation.md`（または同等の処理仕様書）を参照。

| 層 | 資源 | 配置 | 使用技術 |
| --- | --- | --- | --- |
| presentation | `Api` インターフェース | `presentation/api/interfaces` | OpenAPI Generator |
| presentation | `ApiImpl` | `presentation/api/impl/{画面ID_画面名}` | 手動実装 |
| presentation | `Model`（Request / Response） | `presentation/api/impl/{画面ID_画面名}/model` | OpenAPI Generator |
| presentation | Bean マッパ（Model ↔ ServiceDto） | `presentation/api/impl/{画面ID_画面名}/mapper` | **MapStruct** |
| domain | `Service` クラス | `domain/service/{画面ID_画面名}` | 手動実装 |
| domain | `ServiceInputDto` / `ServiceOutputDto` | `domain/service/{画面ID_画面名}/dto` | 手動実装 |
| domain | Bean マッパ（ServiceDto ↔ Entity） | `domain/service/{画面ID_画面名}/mapper` | **MapStruct** |
| domain | `Repository(DB)` インターフェース | `domain/repository/dbaccess/...` | 手動実装 |
| domain | Table Mapper インターフェース | `domain/repository/dbaccess/tables/interfaces` | **MyBatis** インターフェース（MyBatis Generator 自動生成） |
| domain | Query Mapper インターフェース | `domain/repository/dbaccess/query/interfaces` | **MyBatis** インターフェース（手動実装） |
| domain | `Entity`（Table / Query） | `domain/entity/dbaccess/{tables\|query}` | MyBatis Generator（Table）/ 手動（Query） |
| infra | `RepositoryImpl(DB)` | `infra/repository/dbaccess/{tables\|query}/impl` | 手動実装（MyBatis 経由で DB アクセス） |
| infra | Table Mapper 配置 | `infra/mapper/tables` | **MyBatis @Mapper**（`@Select` / `@Insert` / `@Update` / `@Delete` / `@Result`） |
| infra | Query Mapper（XML） | `resources/jp/mufg/bk/{システムID}/infra/mapper/query` | **MyBatis XML** |

> **備考**: 他システム連携・ホスト連携を持たない機能では `Repository(API)` / `RepositoryImpl(API)` はスコープ外。各機能ごとの要否判定は処理仕様書（処理分類）を参照。

> **責務分離（SEPARATION）**:
>
> - **MapStruct** は POJO 変換専用。SQL を書いてはならない。
> - **MyBatis Mapper** は SQL 実行専用。POJO 変換ロジックを書いてはならない。
> - 詳細は [DBアクセス.md](DBアクセス.md) および [設計ルール.md](設計ルール.md) を参照。
