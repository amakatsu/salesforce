## 5. ビジネスロジック概要

### 5.1 一般与信状況計算（computeYosin / computeYosinKeisan）

1. **補正値適用**: 貸付金・商手合計、内円貨、外為与信合計、支払承諾合計の4項目に対し、極度額/本件後残高から補正値を減算（結果が0以下なら0）
2. **合計の積み上げ**:
   - 支払承諾合計 = 支承・一般 + 支承・一般外為 + 代理貸付
   - オンバランス合計 = 貸付金・商手合計 + 外為与信合計 + 支払承諾合計 + 私募債 + 限度算入ローン合計
   - 限度算入与信合計 = オンバランス合計 + オフバランス合計
   - 一般与信合計 = 限度算入与信合計 + 限度不算入与信合計
3. **当月増減額**: 極度額>0 → 本件後残高−極度額、極度額=0 → 本件後残高−月末残高
4. **計算除外項目**: 限度不算入与信合計、年金転貸、指定L/C小切手、L/G、内円貨、協保貸、その他一般与信、特定与信

### 5.2 本件後保全状況計算（computeKokyaku / computeKokyakuShutoku）

1. **規定担保合計（規定値・時価ベース）**: 各担保項目を積み上げ
2. **裸与信**: 限度算入与信合計（本件後残高）− 規定担保合計
3. **規定・優良・商手**: 規定値 + 商手規定値 → 0以下なら空文字

### 5.3 経営指標計算（computeKokyakuKeisan）

- 平均月商 = 純売上高 / 6（中間決算）or / 12（通期）
- 経常利益率 = 経常利益 / 純売上高 × 100
- 当期利益率 = 当期利益 / 純売上高 × 100

### 5.4 市場性与信（computeKokyaku2）

- 科目明細10行分の当月増減額を個別計算（computeYosinと同一ロジック）

### 5.5 保全率計算（computeHozen）

1. **金額単位決定**: 一般与信1タブと市場性与信1タブの金額単位を比較し、大きい方を採用
2. **限度算入一般与信**: 本件後残高を単位変換
3. **限度算入市場性与信**: 本件後与信額を単位変換
4. **規定担保合計**: 規定値を単位変換
5. **保全率** = 規定担保合計 / (一般与信 + 市場性与信) × 100
6. **総合与信** = 一般与信 + 市場性与信
7. **総合信用** = 総合与信 − 規定担保合計（0未満なら0）

## 8. 設計上の特徴と注意点

- **全データをHashtableで管理**: `hstComBasket`（共有情報）配下の`K_DB_DATA`, `K_HOST_DATA`, `K_KEY_DATA`等のHashtableに全計数データを格納。型安全性なし
- **配列添字による項目管理**: `IRingiItemKeisu`の`V_KEISU_*_BAP`定数で配列添字を管理。配列ベースで項目を参照するため、項目追加時の影響範囲が広い
- **計算ロジックの重複**: `computeYosin`と`computeYosinKeisan`、`computeKokyaku`と`computeKokyakuSabunKeisan`はほぼ同一の計算ロジックを持つが、前者はDB値ベース、後者は画面入力値とDB値の差分ベースで動作
- **IBM WACS基盤依存**: `CraftsTrxFolder`, `CraftsDBConnector`, `CraftsDataBean`等のIBM WACS固有クラスに強く依存
- **long型計算**: 保全状況の差分計算は`getDataValue2()`でlong型を使用（金額の桁あふれ対策）
- **BigDecimal使用**: 保全率計算では`BigDecimal`を使用（精度保証）
