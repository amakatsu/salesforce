### 4.3 ステップ6欠番の理由

仕様書のステップ番号は `1, 2, 3, 4, 5, 7, 8, 9, 10, 11, 12, 13` で、**ステップ6が欠番**。

**調査結果:**

1. **仕様書の記述パターン**: Step1〜5はMarkdownの `1.` 自動採番（連番）だが、Step7以降は `7.` `8.` と明示的に番号指定。仕様書の原典ではStep6が意図的に存在していた時期がある
2. **現行ソースとの対応**: `setHostAndDbData()` 内で Step5（ベースデータ作成）と Step7（一般与信計算）の間に独立した処理ステップは存在しない
3. **最も可能性が高い仮説**: Step6は元々「ホストデータとDBデータの統合/マージ処理」として独立していたが、Step5（計算用ベースデータ作成）に統合された。現行ソースの「ホスト⇔DBの引当項目マージ」（計数情報共通クラス.java L4358-4407）がStep5とStep7の間に存在しており、旧Step6の痕跡と考えられる

| 意図 | 補正値を適用して一般与信の極度額・本件後残高・当月増減額を再計算 |

**入力**: 極度額配列、本件後残高配列、補正値配列、月末残高配列、当月増減額配列、実勢現在残高配列、限度算入与信合計配列

**Phase 1: 支払承諾合計の計算**（136〜194行）
```
支払承諾合計 = 支承・一般 + 支承・一般外為 + 代理貸付
※ 全構成要素が空文字の場合は空文字

**Phase 2: 補正値の適用**（212〜239行）
```
極度額[i]     = 極度額[i] − 補正値[i]     （結果≤0なら0）
本件後残高[i] = 本件後残高[i] − 補正値[i] （結果≤0なら0）
※ 補正対象: 貸付金・商手合計, 内円貨, 外為与信合計, 支払承諾合計
※ 空文字の場合は計算せず空文字を維持

**Phase 3: 補正値影響による合計の再計算**（241〜354行）
```
オンバランス合計（極度額）= 貸付金・商手合計 + 外為与信合計 + 支払承諾合計 + 私募債 + 限度算入ローン合計

限度算入与信合計 = オンバランス合計 + オフバランス合計
一般与信合計 = 限度算入与信合計 + 限度不算入与信合計
```

**Phase 4: 特定与信合計の計算**（358〜367行）
```
特定与信合計（本件後残高）= 特定与信1 + 特定与信2
```

**Phase 5: 各行の当月増減額計算**（383〜427行）
```
if 極度額 == 0:
    当月増減額 = 本件後残高 − 月末残高
else:
    当月増減額 = 本件後残高 − 極度額
※ 計算除外項目: 限度不算入与信合計〜L/G、内円貨、協保貸、その他一般与信、特定与信
```

**Phase 6: 合計項目の増減額集計**（433〜542行）
```
貸付金・商手合計（増減額）= 明細1 + 明細2 + ... + 明細12
外為与信合計（増減額）= 輸出小計 + 輸出貸出 + 輸入小計 + 輸入貸出 + 故障指定L/C + ユーザンスシフト外貨

    // 単位が異なる場合は小さい方に揃える
    保全率 = (規定担保合計 × 100.0) ÷ (一般与信合計 + 市場性与信合計)
    ※ 小数点第3位で切り捨て（ROUND_DOWN, scale=2）
    ※ 結果 > 999.99 なら "999.99"
```

**F. 総合与信**（5621〜5659行）（GEC23-C-078）
```
if 一般与信合計 == 空 AND 市場性与信合計 == 空 → 空
else:
    総合与信 = 一般与信合計 + 市場性与信合計（小さい方の単位で計算）
    結果を大きい方の単位に変換して表示（切り捨て）
```

**G. 総合信用**（5664〜5714行）（GEC23-C-078）
```
if 一般与信合計 == 空 AND 市場性与信合計 == 空 → 空
else:
    総合信用 = (一般与信合計 + 市場性与信合計) − 規定担保合計
    if 総合信用 < 0 → "0"
    else → 大きい方の単位に変換して表示（切り上げ）
```
