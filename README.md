## 出力フォーマット（すべて厳守すること！！！）
 
- 出力単位

  - 一つの業務内の画面数が多く遷移図自体が複雑になることが予想される場合は、適切な単位で分割して作成すること。

  - 分割は原則「画面メニュー区分」ごとに行うこととする。（「画面メニュー区分」とは各業務アプリ毎に作成されるホームタブにて表示されている関連業務単位のまとまりのことを指す。画面一覧に記載済）

- ファイル名は当該ページのIDと同じ名称+拡張子とする。

- ファイルの内容は「ヘッダー」、「メイン機能定義」、「関連機能定義」、「画面遷移」の4つのセクションの順番で構成すること。

- PlantUMLのオプション設定（原則不変とする）

  left to right direction

  hide empty description

- ヘッダーのルール

  - ヘッダー部にはページ情報（当該ページのURLや目次、タイトル部の定義）と、PlantUMLのオプション設定を記述する。

  - ページ情報部のみ各ページごとに変更、それ以外は原則不変とする。

- メイン機能定義のルール

  - 当該ページに表現すべきメイン機能を定義する。

  - 全ての画面をバラバラに定義するとわかりづらいため、ある程度の機能の粒度でグルーピングすることを検討する。

  - 各画面に対し、画面IDも併記する。（state ｛画面名｝ : ｛画面ID｝）

  - メイン機能内の画面遷移も記述する。（｛遷移元画面名｝ --> ｛遷移先画面ID｝ : ｛ボタン名｝）

  - 画面名では、・や括弧など利用できない文字が存在する。

    - **その場合、画面名としては利用できない文字を除いた状態で定義し、定義した画面名の後ろに**as "｛本来の画面名｝"** と記載することで利用できない文字を含めて表示する。**

- 関連機能定義のルール

  - メイン機能に対する遷移元画面 or 遷移先画面を定義する。

  - メイン機能に隣接する画面までを表現することとし、遷移元画面のさらに遷移元（遷移先画面のさらに遷移先）などは表現しない。

  - メイン機能の定義部と同様、各画面に対する画面IDも併記する。（state ｛画面名｝ : ｛画面ID｝）

- 画面遷移のルール

  - メイン画面に対する画面遷移情報を記述する。（｛遷移元画面名｝ --> ｛遷移先画面ID｝ : ｛ボタン名｝）

  - 関係画面の情報はテーブル一覧の遷移元画面、遷移先画面、他サービスからの画面遷移からもれなく取得すること

  - 分かりやすさのため、可能な限りメイン画面の画面単位でまとめて記述する。

  - ヘルプ（標準手続へのリンク）など、ほぼすべての画面に設置するような遷移は記載しない

  - 自画面への画面遷移（前後ボタンなど）や閉じる操作などは画面遷移ではないため表現しない。

  - モーダル画面の表現方法

    - モーダル画面はボックスの色を変更する。（色指定：#FF7F50）

    - モーダル画面への遷移は破線で表現する。

  - 注釈

    - 未決事項がある場合など、注釈をつけたい場合はボックスや線に対して吹き出しをつける。

    - ボックスに吹き出しを付ける場合、位置は4つ（left/right/top/bottom）から選択可能であり、分かりやすい位置を選択する。

  - その他、見やすさのための工夫

    - 線の表示形式はモーダル画面への遷移を除き原則デフォルトのままとするが、画面遷移図が複雑で分かりにくい場合には表示形式の変更も許容する。
