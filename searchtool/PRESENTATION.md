## 🧭 要約

まず、要約からお話しします。

### 何をしたか

MCP と Mastra を活用して、統合検索デスクトップアプリケーションを構築しました。

具体的には、3 つの層で実装しています。

1 つ目は、マルチソース検索です。ローカルファイル、Redmine、SharePoint、Teams、社内ドキュメントを並列検索します。

2 つ目は、AI 要約機能です。Mastra エージェントが検索結果を自動的に要約し、重要な情報を抽出します。

3 つ目は、Electron デスクトップアプリです。Windows と Linux の両方で動作するクロスプラットフォーム対応です。

### 何ができるか

このツールでできることは 4 つあります。

1 つ目は、高速なローカルファイル検索です。ripgrep という高速検索エンジンを使い、大量のファイルを瞬時に検索できます。

2 つ目は、複数サービスの統合検索です。Redmine、SharePoint、Teams、社内ドキュメントを一括検索し、情報を一箇所に集約します。

3 つ目は、検索結果の AI 要約です。膨大な検索結果から重要な情報を自動的に抽出し、読みやすく整理します。

4 つ目は、検索履歴とメトリクスです。検索統計、処理時間、ヒット数を追跡し、検索の効率を可視化します。

## 📖 SearchTool とは？

### ツールの概要

SearchTool は、複数の情報源を横断的に検索し、AI が結果を要約してくれるデスクトップアプリケーションです。

開発者や情報調査担当者が日常的に行う、「あの資料はどこにあったかな」「このエラーについて過去に誰か調査してないかな」といった検索作業を効率化します。

### 主な機能

主な機能は 4 つあります。

1 つ目は、統合検索です。複数のソースを同時に検索できます。

具体的には、ローカルファイルを ripgrep で検索し、Redmine のチケット、SharePoint のドキュメント（複数サイト対応）、Teams のメッセージ（複数チーム対応）、そして社内ドキュメントサイトを検索します。

2 つ目は、AI 要約です。Mastra エージェントが検索結果を分析します。

検索結果を自動的に要約し、重要度順にソートして、検索意図を推論します。

3 つ目は、メトリクスとログです。検索パフォーマンスを可視化します。

総検索回数、平均処理時間、ソース別ヒット数、そして検索履歴の最新 10 件を記録します。

4 つ目は、柔軟な設定です。ソースごとにカスタマイズできます。

検索対象ディレクトリ、除外パターン（.git、node_modules など）、タイムアウト、最大件数を制御できます。

### 技術スタック

技術スタックは、フロントエンドとバックエンドに分かれています。

フロントエンドは、Electron 30、React 18 と TypeScript、そして Vite による高速ビルドです。

バックエンドは、Mastra という AI エージェントフレームワーク、MCP という Model Context Protocol サーバー、Playwright によるブラウザ自動化、そして Zod によるスキーマ検証です。

検索エンジンとしては、ripgrep（rg）による高速テキスト検索と、ripgrep-all（rga）による PDF や Office ファイル対応を使っています。

## 🎯 アーキテクチャ

### システム構成

システムは 3 層で構成されています。

まず、Electron App の層があります。ここでは、React UI が検索画面、統計画面、設定画面を提供し、検索サービスが並列検索と結果統合を行い、メトリクスがログ記録と統計集計を行います。

次に、Mastra Agent の層があります。ここでは、AI Agent が検索結果の要約と意図推論を行い、MCP Tools が各検索 MCP のラッパーとして機能します。

そして、MCP Servers の層があります。ここには 5 つのサーバーがあります。

Local FS サーバーは rg/rga を実行します。
Redmine UI サーバーは Playwright で自動化します。
SharePoint サーバーは複数サイトに対応します。
Teams サーバーは複数チームに対応します。
Internal Docs サーバーは自動検索欄検出を行います。

ポイントは 3 つあります。

MCP サーバーが各検索ソースを抽象化していること、Mastra エージェントが検索結果を AI で要約すること、そして並列検索（Promise.allSettled）で高速化していることです。

### データフロー

データフローをご説明します。

ユーザーがキーワードを入力すると、React UI が検索リクエストを SearchService に送ります。

SearchService は Mastra Agent に AI 要約リクエストを送ります。

Mastra Agent は MCP Servers に並列検索を実行させます。

MCP Servers は各ソースの結果を Mastra Agent に返します。

Mastra Agent は要約とヒット一覧を SearchService に返します。

SearchService はメトリクスを記録し、統合結果を UI に返します。

最後に、UI がユーザーに結果を表示します。

このフローにより、複数ソースの検索結果が AI によって統合され、わかりやすく提示されます。

## 💻 使い方

### 画面構成

アプリケーションには 3 つの画面があります。

1 つ目は、検索画面です。キーワード入力欄の下に検索対象ピルと「取り込む最大件数」コントロールがあり、調べたいソースをオン/オフしながら検索できます。実行後は左側に Mastra の要約カード、右側に「統合結果 / Local / Redmine / SharePoint / Teams / 社内Docs」のタブ付き一覧が並びます。

2 つ目は、統計画面です。ここで総検索回数、平均処理時間、ソース別総ヒット数、直近 10 件の検索履歴を確認できます。

3 つ目は、設定画面です。ここで各検索ソースの URL、ローカル検索のルートディレクトリ、除外パターン、制限設定を行います。

### 初回セットアップ

初回セットアップの手順をご説明します。

まず、アプリを起動し、「設定」タブを開きます。

次に、ローカル検索の設定で、ルートディレクトリに検索対象のパスを入力し、除外パターンに .git、node_modules などを設定します。

続いて、Redmine の設定で、URL を入力します。複数行で複数サイトを登録できます。

SharePoint の設定でも、URL を入力します。こちらも複数行対応です。

Teams の設定でも同様に URL を入力します。

社内ドキュメントの設定で、ベース URL を入力します。

オプションとして、ブラウザ設定で User Data Dir を指定すると、ログイン状態を保持できます。

最後に、保存ボタンをクリックします。

### 検索の実行

検索の実行方法をご説明します。

まず、検索タブを開きます。

次に、キーワードを入力し、上部にある検索対象ピルで調べたいソース（ローカル / Redmine / SharePoint / Teams / 社内Docs）を選択します。必要に応じて「取り込む最大件数」も変更します。

Enter キーまたは検索ボタンをクリックします。

すると、左列に Mastra の要約、右列にタブ付き結果が表示されます。「統合結果」タブでは有効化したソースの統合ビューを、その他のタブでは各ソースの結果を確認できます。

## 🔍 実装の工夫

### 3 つの技術的な工夫

このツールには 3 つの技術的な工夫があります。

1 つ目は、MCP による検索ソースの抽象化です。

各検索ソース（ローカル、Redmine、SharePoint など）を MCP サーバーとして実装しました。これにより、新しい検索ソースの追加が容易になり、各ソースの実装を独立して保守できます。

2 つ目は、Mastra エージェントによる AI 要約です。

単に検索結果を並べるのではなく、Mastra エージェントが結果を分析し、重要な情報を抽出して要約します。これにより、ユーザーは膨大な検索結果から効率的に情報を得られます。

3 つ目は、並列検索による高速化です。

Promise.allSettled を使って複数の検索ソースを並列実行します。これにより、全体の検索時間が大幅に短縮されます。また、一部のソースが失敗しても他のソースの結果は取得できます。

### メトリクスとログ

メトリクスとログの仕組みをご説明します。

すべての検索はログファイルに JSONL 形式で記録されます。ログには、タイムスタンプ、レベル、メッセージ、モジュール名、そして詳細データが含まれます。

メトリクスとしては、検索キーワード、開始時刻、処理時間（ミリ秒）、各ソースのヒット数、エラー情報を記録します。

これらの情報は統計画面でグラフィカルに表示され、検索パフォーマンスの分析に役立ちます。

## 📎 付録: 質疑応答想定

### Q1: 検索速度はどのくらいですか？

A: ローカル検索は数秒、Redmine/SharePoint/Teams を含めた統合検索は 10〜30 秒程度です。並列検索により、個別に検索するより大幅に高速化されています。

### Q2: どのようなファイル形式に対応していますか？

A: テキストファイルは ripgrep で高速検索し、PDF や Office ファイル（Word、Excel、PowerPoint）は ripgrep-all で検索します。

### Q3: セキュリティは大丈夫ですか？

A: すべての検索は各ユーザーのローカル環境で実行され、検索結果は外部に送信されません。ブラウザ自動化では、ユーザーのログイン状態を使用するため、アクセス権限も保持されます。

### Q4: カスタマイズは可能ですか？

A: はい。設定ファイルで検索対象、除外パターン、タイムアウト、最大件数などをカスタマイズできます。また、新しい検索ソースを MCP サーバーとして追加することも可能です。
