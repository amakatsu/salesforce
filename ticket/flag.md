
## Redmine QAチケット案

### タイトル
フラグ項目の型と変換方針（0/1 と true/false）

### 背景
- SalesforceはCheckboxでtrue/false
- API/DBは0/1（レガシー）
- 項目ごとに表現が混在している可能性あり
- 変換に外部コード（コードマスタ）を使っている可能性あり

### 確認したいこと
**1. 変換方針（どの層で、いつ変換するか）**
- レスポンス時: APIは0/1のまま？true/falseに変換して返す？
- リクエスト時: フロントからtrue/falseで送る？0/1に変換して送る？
- 変換実装はどの層が責任を持つべきか

**2. ドメイン統一の方針**
- 画面〜DBまで型を統一するか、レイヤー最適で分けるか
- プロジェクトとしてのルールやガイドラインの有無

**3. フラグのコード化ルール**
- 「フラグはコード化しない」ルールは今も有効か
- 外部コードを使う理由と管理場所（Salesforce/バックエンド）

**4. 代替案**
- Salesforce Formulaで数値化する運用は可否

### 期待する回答
- 推奨データ型（Salesforce / API / バックエンド / DB）
- 変換責任レイヤー
- 外部コードの必要性と代替案の可否
- 今後の推奨アプローチ
